## 1. 目标与边界

### 1.1 本计划要回答的问题

1. 论文的**算法主张**（不是工程集成）能否在纯 CPU 的 Python/NumPy 上被独立验证？
2. 验证这些主张所需的**最小实现集合**是什么？
3. 每个模块的**独立 oracle、正/负对照、量化验收**是什么？
4. 哪些部分必须依赖官方 GPU 实现，代价与收益如何？
5. 哪些歧义必须在写第一行算法代码前由科研审查决定？

### 1.2 明确不做（本轮）

- 不做 Isaac Sim / MuJoCo / ROS 2 / 双 FR3 的集成或适配；
- 不追求表 II 的逐格数值复刻（缺场景、缺基线、参数不一致）；
- 不把通用 MPPI 当作两阶段方法的替代品来"通过验收"；
- 不在 G1–G3 中安装 CUDA/PyTorch/cuRobo（模块 G 单列，且需单独批准）；
- 不复制上游源码入库（无许可证）。

## 6. 最小忠实复现（推荐）

**定义**：在**不安装任何重型依赖**的前提下，用 4 个模块回答论文的 4 个核心算法主张：

1. **A2 + A3**：相对/绝对位姿与相对雅可比是自洽的、可被独立 SE(3)/有限差分验证的（含式 (8) 的纠正）。
2. **B1 + B2**：零空间投影在代数上正确，在有限步长下是一阶精确、二阶残差；秩退化行为符合 Remark 2。
3. **D1–D3**：k-means + 精英众数 + 簇条件聚合确实消除模式平均；第二阶段确实降低方差而不牺牲精度。
4. **F1**：在等预算、同种子下，两阶段的抖动显著低于单阶段，且不能用"温度更低"解释。

**不做**：表 II 逐格数值、真机、动态障碍、GPU 绝对时延。

**预期结论强度**：可以声称"复现了论文的两阶段采样机制与零空间约束机制，并在受控任务上验证了其宣称的定性优势"；**不能**声称"复现了论文的实验结果"。

**若科研审查要求表 II 级复现**：那是另一个项目，需先解决 §7 的 6 个缺口，估计 6–10 周，且需要 cuRobo + GPU + 场景反推；不建议与 G1–G3 合并。

## 10. 停止条件

出现以下任一情况，停止并请求科研审查：

1. Q1–Q10 中有任何一项未决而实现必须依赖它；
2. 某模块的负对照无法失败（说明 oracle 或实现有问题）；
3. 两阶段优势在预登记实验中不显著，且需要改变任务几何才能显著（可能是任务设计而非算法效应）；
4. 需要安装 CUDA/cuRobo/ROS 2 才能继续（进入 G4 授权流程）；
5. 需要复制上游源码才能继续（许可证不允许）；
6. 任何会改变论文算法语义的"便利修改"。
