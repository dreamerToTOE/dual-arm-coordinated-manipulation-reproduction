# P2-T01 计算预算与性能审查

**结论**：当前实现下，一个 95 s 运输案例约需 **560–830 s 墙钟**（实测外推），30 案套件约 **18–25 ks（5–7 h）**，
是冻结预算（120 s/案、7200 s/套）的 **3–4 倍**。瓶颈不是动力学积分，而是**测量更新**（约 77% 墙钟）。
需要先做一次**不改变数值语义**的热路径优化，再冻结新预算；否则 T06 起的实验无法在预算内完成。

数据来源：`p2/reviews/T01_COST_PROBE.json`（`p2/tools/t01_cost_probe.py`，总墙钟 6.6 s，远低于 PRE 授权的 60 s）。
所有数字标 `ENGINEERING_SMOKE`，不是科学结论。

---

## 1. 时间口径（先把分母说清）

| 记号 | 含义 | 值 |
|---|---|---|
| `t_paper` | 论文可比时间：抓取后运输，含 7 s 力控、13 s 位姿、76 s 末路点、95 s 结束 | 95 s |
| `t_settle` | 本实现新增的 5 s 重力沉降（论文未描述） | 5 s |
| `t_sim` | 一个案例的仿真总时长 = `t_settle + t_paper` | **100 s** |
| `t_precal` | 75 对预标定，仅计算不推进物理时间 | 0 s 物理 |
| `T_wall` | 实际墙钟 | 实测 |
| `R_phase` | 相位实时比 = `T_wall_phase / t_sim_phase` | 分相位统计 |

**必须分相位**：settle 阶段没有滤波更新，只有 plant + 日志；transport 阶段才有滤波。用总比 `24.94/8.948 = 2.79`
去乘 100 s 会**低估** transport 的真实成本（把便宜的 settle 混进了分母）。

用旧失败案例反推：`T_wall = 24.94 s`，其中 settle 约 1.9 s，则 transport 段约 23.0 s / 3.948 s =
**`R_transport ≈ 5.83`**。按此外推 `95 s × 5.83 ≈ 554 s`，加 settle ≈ 556 s/案。
用组件成本自下而上估算则为 **约 830 s/案**（§2），两者给出区间 **560–830 s**。

> 因此 T00 里的"95 s ≈ 279 s"作废：那是把 settle 计入分母的错误外推。审查意见要求的"按真实分母重新冻结"即指此。

## 2. 组件成本（实测）

| 组件 | 实测 | 说明 |
|---|---:|---|
| 导入 numpy | 65.6 ms | 一次性 |
| 导入 scipy | 36.1 ms | 一次性 |
| 导入 P2 模块 | 32.1 ms | 一次性 |
| 读协议 JSON | 0.29 ms | 一次性 |
| native 缓存校验 + 加载 | 1.44 ms | 命中缓存，未重编译 |
| **固定初始化合计** | **≈ 135 ms/案** | 可忽略 |
| `native.contact` | 0.0358 ms | 每次采样/质检调用 |
| `native.advance`，1 步 @1/3000 | 0.0826 ms | 瞬态、按 12 步批处理 |
| plant 实时比（纯积分，0.5 s 瞬态） | **0.248×** | 即 100 s 物理 ≈ 24.8 s 墙钟 |
| `continuous_linearization`（42×42） | 0.257 ms | 每次预测都调用 |
| **一次预测（4 ms，有界先验）** | **3.37 ms** | 约为实时预算 4 ms 的 84% |
| **一次更新（3 观测包）** | **32.1 ms**（min 21.6 / max 44.6） | 5 次内迭代；瓶颈 |
| 42×42 `expm` | 0.289 ms | 稳定格式候选 A |
| 84×84 `expm`（Van Loan） | 0.682 ms | 过程噪声精确离散 |
| 日志 plant 行 | 8.0 KB/行；序列化 0.224 + gzip 0.251 = **0.475 ms/行** | 250 行/s |
| 日志 estimator 行 | 9.3 KB/行；0.179 + 0.200 = **0.379 ms/行** | ~410 行/s |

**更新为什么 32 ms**（`cProfile`，5 次更新共 0.227 s）：`validate_transform` 平均**每次更新被调用 103 次**、占 44%；
小规模 `numpy.linalg.solve` 每次更新约 **42 次**、占 27%；`se3_log` 每次更新约 **30 次**、占 24%。这是 Python 层几何原语的重复校验与
逐观测重复求 Jacobian，不是线性代数规模问题。

## 3. 单案预算（`t_paper = 95 s`）

事件率取自旧失败案例：更新 210/s、预测 410/s、plant 日志 250/s。

| 项 | 计算 | 墙钟 |
|---|---|---:|
| 测量更新 | 95 × 210 × 32.1 ms | 640 s |
| 预测 | 95 × 410 × 3.37 ms | 131 s |
| 动力学积分 | 100 s × 0.248 | 25 s |
| plant 日志 | 23750 行 × 0.475 ms | 11 s |
| estimator 日志 | 38950 行 × 0.379 ms | 15 s |
| 传感器生成 | ~45600 次 × ~0.08 ms | 4 s |
| **合计（自下而上）** | | **≈ 826 s** |
| **合计（实测外推）** | 95 × 5.83 + 2 | **≈ 556 s** |
| **规划取值** | 取两者之间偏保守 | **600 s/案** |

30 案（20 主 + 2 高力矩 + 2 延迟 + 1 滑移 + 4 GT 诊断 + 1 半步）：
`29 × 600 + 265（30 s 滑移案） ≈ 17.7 ks ≈ 4.9 h`；按 830 s/案上限则约 **24 ks ≈ 6.7 h**。

冻结预算为 **120 s/案、7200 s/套** → **超 2.5–3.4 倍，当前不可执行**。

## 4. 优化方案与优化后预算

| 编号 | 措施 | 类别 | 预期收益 | 风险 |
|---|---|---|---|---|
| O1 | 热路径：内部调用跳过重复 `validate_transform`；`se3_log` 用旋转矩阵→rotvec 的本地实现替代 scipy `Rotation`；选择器与常量缓存；每个观测的 Jacobian 只算一次 | 工程，**不改数学** | 更新 32 → 6–8 ms；预测 3.37 → 1.2–1.5 ms | 必须证明等价（逐分量 ≤1e-12 或位相同），否则回退 |
| O2 | 日志降频：estimator 行 50 Hz（保留每次更新的收敛/创新摘要）、plant 行保持 250 Hz（半步门需要） | 工程 | −10 s/案 | 需声明"未记录的中间事件仍参与计算" |
| O3 | 预计算 `Φ`：同一 mode/工作点下缓存 `expm(hA)`，状态变化超阈值才重算 | 数值近似 | 预测再降 0.3 ms | 属近似，需单独版本化 |
| O4 | 把测量 Jacobian 与更新下移到 native C++ | 工程（较大） | 更新再降 3–5× | 开发量 3–5 天，需独立资格 |
| O5 | 主实验 seed 5 → 3 | **科学**，需批准 | 20 → 12 主案 | 降低统计强度，不得擅自做 |

**优化后（O1+O2）单案**：更新 95×210×7 ms = 140 s；预测 95×410×1.4 = 55 s；plant 25 s；日志 15 s；杂项 5 s
→ **≈ 240 s/案**。30 案 ≈ **7.0 ks**，刚好落在 7200 s 内（余量 3%）。
若 O1 只做到 10 ms/更新，则 ≈ 310 s/案，30 案 ≈ 9.0 ks，需要拆分套件或提高总预算。

## 6. 提前停止条件

任何一条触发即停止整套并保存现场，不自动续跑：

1. 单案墙钟 > 400 s（未优化回退 900 s）。
2. 套件已用墙钟 > 7200 s 的 90%，或"按当前均值外推的剩余成本 > 剩余预算"。
3. 首个 `FAIL_STOP`（沿用旧 runner 行为）。
4. 估计器连续 3 次不收敛（沿用冻结判据）。
5. `ρ(Φ) > 1+1e-12`、`P` 失去 SPD、或出现 `COVARIANCE_ASYMMETRY`（稳定格式启用后）。
6. 同一 blocker 已用满 3 次有依据的修复。
7. 实测更新成本 > 预测值 1.5 倍（说明优化未达标，先停再评估）。
