# 导师要求的论文复现汇总报告格式（DEFORM 示例提炼）

## D082 — 五篇报告分成两类（2026-10-19；新最高优先级交付口径）

**P4：算法与完整虚拟仿真报告**。第一部分原论文问题/数学模型/核心算法与图表定义，第二部分**一套真实可复现的闭链虚拟规划任务**的起终点、障碍、路径、闭链残差/碰撞/分支、RSS/PCS/NR和full/fixed-PCS对照、数值曲线/统计、原论文实际条件/差异；最后独立双FR3应用与不足章。完整仿真不是“原论文六环境×全部500次完美复现”，取消的18,000次和未实现的原环境及图表必须公开在最终对照表。

**P1/P2/P3/P5：核心算法数值复现报告**。无需任务级完整仿真/实体硬件。前部仍应详细解释原文核心数学创新、模型、推导与算法代码；后部展示真正运行的确定性数值实例/单位与独立oracle/残差或收敛检查（必要时图表），逐项标出与原文整套实验的差别、失败与未实现模块；末章依旧分析FR3潜在可用思想（不执行工程适配）。若核心创新没有实现，不能靠组件数学检查就称算法完整通过；单篇完成后向用户交真实Word/PDF及[原文/本次批准/实际覆盖]三栏对照表。

**D082高于下文D079/D078在实验实施范围方面的旧规定**，但不取消原文阅读、实测真实性、版本/失败保全、三次失败归因或原算法/适配分栏。详见[五篇新决策](decisions/D082_FIVE_PAPERS_ONE_VIRTUAL_SIM_FOUR_ALGORITHMS_20261019.md)与[P4执行任务](tasks/P4_D082_VIRTUAL_SIMULATION_EXECUTION_20261019.md)。

## D079 — 用户更新：原文全文义务先审计，任何实验不得擅自省略，三次失败后必须归因（2026-10-14）

D079高于D078/D065/D064在缩小原论文复现范围方面的旧规则。Codex每篇论文必须先重读英文原文全文、图/表/公式/附录及可取得的补充材料和作者源码，将**原文需要复现的全部核心算法、模式、场景、对照、消融、统计、鲁棒性与完整系统实验**登记进唯一ID的覆盖矩阵。必须对照原文逐项执行，不能因为“最小可复现”“时间有限”“作者没有全部资源”而在任务清单里自行删除条目；作者缺资则列出取证和物理/算法等价重建路径，并标注重建限制。详情：[全论文覆盖、三次失败根因规程](REPRODUCTION_FULL_PAPER_COVERAGE_AND_ROOT_CAUSE_PROTOCOL.md)。

三次有据修复仍失败时强制最小反例、原作者模型/代码交叉核查、实现/数值/感知/环境差异诊断。若我方问题，提交新修复和资源方案后继续验证；若原论文本体缺关键数据且无法可信重建，标明 BLOCKED-PAPER-RESOURCE（不是论文算法错误）；疑似原公式矛盾须独立反例和科学证据，只标SUSPECTED；未能区分时标UNKNOWN，不猜测。重试与预算受预注册和用户批准约束，不无穷跑。

每篇结题必须提交并**主动展示给用户审查**：[原论文与我们实际复现范围对照表模板](../reports/PAPER_ORIGINAL_VS_REPRODUCED_MATRIX_TEMPLATE.md) 的逐项更新版Markdown和CSV，以及完整科研Word/PDF。每行写原文出处/实验条件、我们真实条件、数据分母、实验失败和原因、严格原样还是独立重建，以及论文与我们结论的可比性；未完成不能冒充FULL。最后一章仍强制详析双FR3可复用的方法、模块、适配接口、物理先决条件和未来对照方案，只做研究分析不做现在的场景改造。

P4任务清单：[29项逐项义务](tasks/P4_ORIGINAL_FULL_COVERAGE_AND_RECOVERY_20261014.md)；P2任务清单：[33项逐项义务](tasks/P2_ORIGINAL_FULL_COVERAGE_AND_RECOVERY_20261014.md)。所有旧成果原件保全，新任务只在用户已授权的研究范围内开新run_id。

## D078 — 所有论文必须验证核心创新，并在末章具体分析对本课题的借鉴（2026-10-14，用户新决定，优先于以下旧范围）

**适用于 P1/P2/P3/P4/P5 全部论文，且此规则不因导师催促而缩减：**

1. 每篇论文应以作者原始研究问题为中心列出核心创新、论文每组关键环境、比较算法/控制器、必要消融/困难测试；建立逐项复现覆盖矩阵（原条件、实际实现、真实结果、缺失/差异、理由），不允许仅完成一个最容易的代表环境就将整篇称为完成。不能获得的作者输入先查代码/资产/许可，再合理独立重建并明确标注；如果确实无法验证则标记阻塞与 PARTIAL。
2. 对原文最重要的现象必须**设计能够证伪的实验**，不要只测试组件能否正常运行。例如 P4 要覆盖六环境及复杂障碍，验证 PCS 与 RSS/NR 的相对表现，并对 PCS 使用固定划分消融与切换机制见证，而不是仅报告 PCS 20/20。
3. 所有比较在同任务、同碰撞/接触模型、配对种子和可解释的同预算下进行；如作者分别调优参数，另外保留原文对齐协议。按真实成功、失败、超时和时钟分别统计；不得事后择图或挑种子来制造原文趋势。重要规模缩减先说明资源与用户裁决，不默默称为“完整”。
4. **最后必须独立设置“本文可迁移至双 FR3 场景的方法、原理及扩展边界”章节（每篇强制，不是可选展望）**。必须逐算法/模块给出：方法解决什么问题 → 原论文证据及本次实测资格 → 当前 Benchmark A 双臂共同搬运和 Benchmark B 单臂推入的适用阶段（或不适用）→ 输入/输出与接口（ROS2/MoveIt2、关节状态、物体位姿、FCL、力传感等）→ 必需的模型/观测/机器人硬件或 Isaac 物理能力 → 适配方案与关键方程/控制架构 → 与现有做法的关系及候选对照实验 → 潜在失败/安全约束 → 是否推荐、为什么以及证据等级。
5. **证据标签严格分层**：[ORIGINAL] 原论文、[REPRODUCED] 在可说明条件下真实验证、[ADAPTATION] 有差异的实现、[PROPOSED] 尚未实现的方案、[BLOCKED] 没有合格结果。不得把方法迁移的构想写成已证明改进。五篇论文完成后再决定是否统一迁移 Isaac；当前末章只做详细预研，不启动场景代码。
6. P4 继续扩展的执行入口是 [P4_FULL_ENVIRONMENTS_PCS_VALIDATION_20261014](tasks/P4_FULL_ENVIRONMENTS_PCS_VALIDATION_20261014.md)。旧 P4/P2 科研结果、失败、3/3 修正记录与冻结结论均为历史证据，新续研另立独立分支与审查预算，不回写旧成果。

以下历史 D065/D064 是先前已执行的交付规则，遇到与 D078 冲突时以上述**更严格的科学覆盖与应用分析要求**为准。

## D065 — 报告以我的科研汇报口吻、三方法实测为中心（2026-10-13）

**开头直接进入学术研究，不写“编写目的、编写说明、根据你的要求、按照导师要求、当前阶段门禁、报告定位、本章定位”等说明性文字**。允许自然第一人称（“我研究了……我实现了……实测结果显示……”），尽量用科研事实、推导和客观结论行文；不得把Codex/ChatGPT工作指令或审查程序搬入交给导师的正文。

P4作为原文**三方法比较研究**，正文不满足于NR：RSS/PCS/NR三法都要尝试忠实实现，最少同条件可重复跑出各自真实结果，再作对比；部分方法没有源码或修正三轮仍失败，则诚实记录失败/原因/尚未复现，不制造漂亮图。图表按“原论文结果”和“我们实测结果”明确分开，绝不混成同一实验组。

固定顺序：**原文数学模型/算法和三法机制 → 原论文实验设计 → 本次复现条件与三法结果 → 与论文实验对照及失败 → 最后独立一章‘应用到当前双机械臂课题的差距与问题’**。其他论文按同样模式重构，且不强制使用现有FR3/Isaac模型。源码不全允许最多三轮可审计的小幅修正，届满无匹配结果按真实值报告；不改变预声明门限与对照条件。

详见 `docs/tasks/P4_THREE_METHOD_COMPARISON.md`。


## D064 报告重心调整（2026-10-13）——高于下文早期提纲

**报告必须先讲清“论文提出了什么算法/控制器”，再讲“我们复现了哪个算法及图表结果”；应用到当前双FR3车厢任务的差距独立放在最后一章。** 不应把FR3关节余量、车厢宽度、吸盘抓取或Isaac集成前置为算法复现成果的主线。前约80%的报告正文以论文原模型、原算法、原论文实验条件、实现忠实度、最小实测结果与对应对比为主。

建议结构：**第一部分 原论文数学模型与核心方法** → **第二部分 原论文算法的复现、仿真及结果对照** → **最后独立章节：在我当前双FR3/Cube/受限车厢场景应用时的差距与待解决问题**。最后章节讨论即可，不以之作为现阶段复现通过条件。对其余四篇控制论文，强调控制器结构（观测量、控制律、执行器输入、闭环、核心假设），不要泛写“先对接Isaac/吸盘”；平台优先论文对应系统或最小模型。

本报告每一段可按**原论文事实（带原式/图/表）/我们真实复现及证据/尚未复现或条件差异**核查。保留分项失败与局限，但不要让它取代原论文公式讲解。完整P4专项见 [P4报告重构任务](tasks/P4_REPORT_REFOCUS.md)。


依据用户上传的 18 页 `第4篇DEFORM论文复现汇总  2026.10.12.docx`；此文档未公开收入 GitHub，个人阅读副本按 `references/ORIGINAL_PAPERS.md` 放置。

## 第一部分 数学模型（对齐原论文）

1. 题目、作者、期刊、年份、DOI，复现研究问题和论文原创新点；严禁仅把方法做成清单。
2. 算法整体流程图：状态/测量输入、约束、核心计算、输出与闭环反馈。标注原论文的图/算法/公式编号。
3. 系统模型与假设：机器人/物体运动学或动力学、坐标系、控制与状态、输入、边界/接触假设，给出**实际使用的公式**。
4. 核心算法逐节讲清：每个变量和代价/约束的物理意义、怎么计算、怎么用于循环；没有复现的原文关键点必须标注。
5. 原论文与我们实现逐项对照表（原方法／精确复现／必要适配／简化／未实现）。尤其 P4 不可漏掉 RSS/PCS/NR 对比本质。
6. 结果评价方法：原论文怎样定义误差、成功、耗时、碰撞或力控指标；和我们的判据是否同义。

## 第二部分 仿真复现实验（必须是实际运行记录）

7. 实验环境与参数表：软件/版本/机器人模型/采样周期/预测时域/约束/求解器/种子/重复次数；每项写“来自原论文／自行设定／模型差异”，不要靠猜。
8. 仿真验证内容：数学测试、最小任务、原论文相关实验对照，**先锁定条件后运行**。
9. 运动或力控主要结果：末端/物体轨迹，误差时间曲线，规划搜索或投影收敛、接触力/内力等本篇最关键量。
10. 基本成功与失败统计：真实试验次数分母、终止原因、运行耗时、异常案例；可视化需要有中文图题、轴单位、图例和正文解释。
11. 困难场景与独立核验：只有实际做过才写，注意数值与物理证据、离散碰撞与连续安全的区别。
12. **与原文结果对照表**：原论文表/图对应值、本次值、机器人/场景/起终点/机器/定义是否可比；不能因条件不同宣称“优于论文”。
13. **已完成内容与原文差距**：真实满足哪些结论，哪些因物理场景/感知/原算法分支而未完成；负面数据保留。
14. **代码与结果怎样使用**：可复现实验指令、Git提交与数据/绘图入口、文件清单及风险，不公开未经授权的原论文 PDF/参考DOCX。

## 图表建议

- 至少一张清晰的论文算法流程图、一张系统/几何示意图和一张从真实实验数据绘制的核心指标图；按可用证据增加误差随迭代/时间、轨迹、控制量、成功率和方法对照。
- 不为凑18页制造结果。可以少于范例页数，但公式与结果要足以支持科研复现报告。
- 图中文字必须使用可显示中文的字体；不得再出现口口乱码。优先使用向量格式或足够清晰的位图；导出 Word 后必须检查实际页面。
- 图表注释标明结果性质（原文复刻/新模型/场景适配/工程修正）、样本数和单位；不可把轨迹点序号误写成物理时间。

## 报告质量门禁

读完全文才开始引用。引用以原文 DOI/图/式/表为准，工程结果来自固定提交与保存日志。保存可编辑Word、数据和绘图脚本；明确区分“原论文方法”“我所做的复现”“尚未复现”“后续考虑的小改进”。Word 用第一人称科研汇报口吻，而非自动生成测试流水账。每篇报告上传前等待用户审查。
