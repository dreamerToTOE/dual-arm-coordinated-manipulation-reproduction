# D079 — 全论文复现覆盖、失败归因与交付总规程

> **2026-10-19 D082 范围更新**：本文件的原论文**全文义务审计表和根因规则继续使用**，但不再要求P1/P2/P3/P5实际运行所有原论文任务/硬件实验；这四篇只需核心算法数值复现。只有P4需要额外完成一套可信虚拟仿真实验，原18,000次取消、VI归档。每篇结题仍映射“原文义务 / 新批准范围 / 实际实测”，保留缺项且不称全文FULL。参见[最高优先级D082](docs/decisions/D082_FIVE_PAPERS_ONE_VIRTUAL_SIM_FOUR_ALGORITHMS_20261019.md)。下文旧“不得省略任何实验”的要求只作原论文事实覆盖与历史记录，不是当前执行授权。

2026-10-14 用户新决定。适用于 P1、P2、P3、P4、P5，优先级高于历史“代表环境/最小复现/3轮后直接停止”等范围缩减规则。用户要求**完整复现原论文需要的内容，不得由执行者擅自删实验、换成简单环境或省掉某个算法分支。** 全文原论文先读完，再设计实验，再由 Codex 执行。P4/P2 既有交付均保留为真实历史、PARTIAL 状态；本规程不追认旧结果为全文复现。

## Gate R0 原文完整审计：在编码之前冻结“全文义务表”

1. 优先阅读拥有来源校验的论文最终发表版；如仅取得作者 accepted manuscript，明确版次、DOI、SHA256、页数和可能差异。阅读全文、附录、补充材料、视频说明及作者源码/运行脚本（可访问时），逐页建引用，不得只读摘要、表格和报告二手总结。原文不存在或外部资产不可获取，记录检索日期、URL、版本、许可证和尝试记录；不要推断或杜撰。
2. 将**论文实际声称的所有贡献**及支撑其结论的每一个实验拆成独立原子义务行：原式/图/表/章节、预期现象、原方法和参数、原环境与机器人/物块、执行器/传感器与噪声、种子/重复次数/时长/预算、对照/消融与指标、输入数据依赖、独立验收方法。论文里的关键论断没有实验直接支持时标 PAPER-CLAIM-NOT-DIRECTLY-TESTED，设计独立核验（新增实验另列，不伪称原论文实验）。
3. 所有行强制分栏：【原文事实】【原文证据和材料可得性】【我们已复现的内容及保存日志】【差距】【拟完成的完整复现任务及验收】【实际判定与证据】。每行唯一 ID，可追踪到代码配置、实验run、图/表、Word段落。
4. 不能以“时间紧”“别的环境太复杂”“作者只有部分源码”“数学测试已通过”删除义务。无合法原资产时，先做来源检索、已知尺寸的认证重建及作者方法等价性论证；重建同类场景必须标 INDEPENDENT-RECONSTRUCTION，不能宣称 ORIGINAL-EXACT。原论文特定硬件不可获得时，明示硬件级实验 BLOCKED-EXTERNAL，同时可另做具备物理机制的模型仿真；两者证据不得混同。
5. Gate R0 输出：paper_source_manifest.json、ORIGINAL_FULL_COVERAGE_MATRIX.csv/md、缺失资产和许可证账本、预注册实验协议、计算预算、科学阻塞和决策清单。**覆盖矩阵缺行、某原文关键图表无对应行，禁止宣称 READY / FULL。**

## Gate R1 模型、算法和物理/数学资格

按全文义务表构建所有平台、算法、相关模式/分支、物理和观测通路。首先用可核实的单元/有限差分/解析/负例/守恒或物理因果测试识别源码错误；再单独完成闭环/路径运行资格。技术层级：数学/单组件 PASS ≠ 完整系统或方法主张 PASS。
区分：原文方法精确重建（含原参数） / 证据明确的重建输入 / 额外工程适配。对于本轮仍未实现的全关节、物理接触、真实观测、规划器或机器人模型，不得拿单位矩阵、伪造输入、解析结果替代完整实验并计 PASS。

## Gate R2 全实验矩阵复现与独立验收

- 将原文所有方法×环境×规划器×接触模式×控制开关×难度级×种子/重复，按原文范围展开，每个实验行事先冻结配置、随机流、时间戳/计算预算、结果度量、成功/失败、退出机制和对照组；不要运行后更改。
- 能做到原文规模的尽量对齐；超额资源必须提供可执行量化预算并请求用户审核，而非秘密缩成 5 seeds/5 sec 后标全文 PASS。可将小样本 smoke/pilot 置于单独诊断账本，正式样本不得混入。
- 每组必须保留正反例与失败。外部依赖不可运行时记录文件/版本/原因，评估等价合法模型；缺失即标 BLOCKED，不可从统计分母消除失败或挪用作者图表。
- 报告所有原文图、表和关键论断的可比结果：单位、机器、样本分母、截断预算/超时、真实规划/控制指标、时域、误差定义、重复性、不确定性。原作者结果与本机结果单独呈现，不跨平台夸大优劣。

## Gate R3 三次失败后的强制根因诊断（不是自动放弃论文）

**计数单位**：相同失败机制/同一研究假设的最多 3 次有记录的修复或重复尝试，按源码SHA、输入/seed、运行日志、与前次的唯一变化逐项保存；初次失败和每次修复的顺序不得倒填。单纯重新运行相同输入而没有新增证据不能算有效修复。

第3次仍未解决，强制暂停该问题的盲目重跑，提交 FAILURE_ROOT_CAUSE_REVIEW.md，必须完成：
A. 最小失败证据：失败最早时刻、具体接口/约束/观测/投影/控制分量、可重复正负例、最小反例、复核运行与是否与原文同条件。
B. **OUR-IMPLEMENTATION**：源码错误、坐标/符号/时钟、机器人几何、参数/阈值、数值积分/求解器、碰撞/接触、IK分支、估计初始化、随机采样、场景难度选择、适配不等价、硬件资源/性能等我们造成的因素。进行消融、官方源码或独立 oracle 交叉核验，列可证伪假设。
C. **PAPER-REPRODUCIBILITY-LIMITATION**：原论文/补充材料缺少关键参数、作者代码缺少实验环境或必要数据、许可证及无法获取的专用硬件，且这些缺口已通过可靠公开资料/作者资产审计和有证据的重建尝试证明无法确定原条件。标“无法精确复现”，不等于算法/论文理论错误。
D. **PAPER-METHOD-ISSUE-SUSPECTED**：原式内部矛盾、不可行条件或方法在其声称适用条件下可重复违反结论。只有独立公式推导、可检验反例、作者实现/高精度参考与反向假设排除后才可报告“疑似原文问题”；未与作者实际实现核实时不得认定论文错误。
E. **MIXED / UNKNOWN**：证据不足、数值和模型偏差交织。不得归咎于论文，更不得以此默认为科学完成。
F. 五分类为每个独立 failure_id 赋予 evidence URL、置信级别、不能排除的竞争解释、下一试验动作、必要的用户批准和预算。

**若证据为 OUR-IMPLEMENTATION**：必须针对真因提出可测试的修复，不允许以第三次为终点。先最小单测/独立oracle，再修复并复核影响范围，保存全部旧数据；在**新声明的修复计划、时间/计算预算与必要科学假设变更审批**后继续正式矩阵。再次连续三次仍失败，重新从根因诊断而非机械重跑；不能无限扩大资源，也不能暗改原算法/参数来跑过门槛。
**若是论文可复现性限制**：记录详细来源、缺失的不可辨识输入和重建尝试，相关行标 BLOCKED-PAPER-RESOURCE；可交付已证实的独立重建，但不称精确全文复现；不允许泛化为“原论文方法错误”。
**若可能是原文算法数学/科学问题**：保持原式对照和独立反例；经不含我们适配误差的验证仍冲突，标 PAPER-ISSUE-SUSPECTED，提交科学审查，不能私自修订原公式后称严格复现成功。
非科学 bug（路径/日志/JSON）优先不占科学修正次数，但必须保留完整变更；实际每次实验执行和成本单独记账。任何真实机器人安全、法律、许可证和不可逆操作需独立批准。

## Gate R4 逐篇结题前的全文覆盖审查

一篇论文从“重现任务已完成”结束前，强制逐条核对 Gate R0 矩阵：**每行必须有真实复现证据或有证据的 BLOCKED/FAILED 结论，不允许留 NOT_ATTEMPTED、缩减范围、无说明的 OMITTED**。完成各实验的图、数值、失败归因、统计报告、实际命令、代码/配置/日志哈希、独立复核工具、中文 Word/PDF。
只有每项论文核心贡献及实验均在原义务条件下成功或等价且经核验的严格对应条件下验证，才能标 FULL。否则根据证据标 PARTIAL / BLOCKED；“全部行处理完”不代表“全部复现成功”。
**完成论文（包括无法完成且有可靠阻塞结论的情况）时，必须交付并展示更新后的“原论文与我们实际复现范围对照表”，逐行包括 FULL/RECONSTRUCTED/PARTIAL/FAILED/BLOCKED 的真实判断。必须让用户看到表格和链接，用户审查之前不得自行动下一篇。**
报告末章强制对当前双 FR3 两阶段 Benchmark A（双臂侧吸共同搬运）/B（右臂单吸推入）逐项分析可迁移的原理、接口、必需前提、关键约束、模型不适用因素、失败风险、未来对照实验，按 [ORIGINAL]/[REPRODUCED]/[PROPOSED] 证据分栏。此阶段只预研，不修改 FR3/Isaac/ROS。

## 版本保全与接续

- 本轮新规程不更改任何既有 P2/P4 accepted branch、旧 Word、旧日志、旧 3/3 科研修正记录。所有新增实验建立新 branch/目录、唯一run_id与新增预算。P4 已有Codex独立运行，避免同时重写其工作树；用 GitHub 新规范分支的明确文件 URL 同步要求，Codex 切换前先检查和保全工作状态。
- 先完成 P4 扩展覆盖、复核报告并向用户提交最新 FULL_COVERAGE_MATRIX；另分支恢复 P2 真正闭环与未做的装配/滑动/多率实际机制。若用户允许独立并行，应分离资源和分支。
- 任何原始输入、独立重建几何或用户新批准偏差，都必须留审计 ID；不因“方便出图”改变作者物理控制律。
